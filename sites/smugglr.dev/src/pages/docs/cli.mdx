`--discover` prints, for each place, its identity (for D1, the account and the database’s uuid), its ledger, its tables with rows and bytes estimated from a sample of 1,000 rows, the copy order, self-references, triggers, views, indexes and ignored tables. A finding comes first and the exit code is 3:

<WrapCode>{OUT.discover_stop}</WrapCode>

When nothing blocks, the same report ends `shapes: the same` and the exit code is 0. With `--json` the report carries `identity`, `ledger`, `blocking` and `shapes_match`. A sync that stops with exit 3 or 5 ends its stderr with the `--discover` command for the same two places.

<WrapCode>{OUT.discover}</WrapCode>

A sync writes a parent’s rows before its children’s, so a place that enforces foreign keys, as D1 always does, takes them. `smugglr --version` and `-V` print the version and exit 0:

<WrapCode>{OUT.version}</WrapCode>

smugglr keeps no secrets and has no environment of its own; it reads the two D1 variables from the environment it runs in. Set them however you keep them:

<WrapCode>{"CLOUDFLARE_ACCOUNT_ID=<account-id> CLOUDFLARE_API_TOKEN=<token> smugglr sync ./shop.db d1://shop"}</WrapCode>

Other database engines (postgres://, for example) are refused: smugglr keeps SQLite in step with SQLite. Every table needs a primary key; a table without one stops the run with exit 3. SQLite’s `sqlite_*` tables are always ignored, and so are D1’s `_cf_*` tables.

</ManualSection>

<ManualSection id="exec" note="smugglr exec, for migratr">

`smugglr exec` runs a migration’s statements on a place for migratr, so that a schema change can reach a place such as D1 through smugglr. migratr 0.3.0 calls it from `migratr dev`, `up --smuggl` and `down --smuggl`; `smugglr --help` does not name it.

<ManualTable
  head={["command","what it does"]}
  rows={[
    [
      "smugglr exec <local> <place> --version <v> --up|--down --expect <fingerprint>",
      "Reads a JSON array of statements on stdin and runs them on the place in one all-or-nothing batch with the version’s ledger row, or its removal for --down. It runs only when the batch’s SHA-256 equals the up or down hash the local database recorded for that version, and the place’s structural fingerprint is the one --expect names. A down batch needs the local database to have run the down first. It prints the place’s fingerprint after."
    ],
    [
      "smugglr exec <database-or-place> --read",
      "Prints the schema, the ledger and the fingerprint, as one JSON object. It takes no query."
    ]
  ]}
/>

<WrapCode>{OUT.exec_read}</WrapCode>

A D1 place and a file in the same shape have the same fingerprint. A refusal exits 3 and leaves the place as it was; a failing statement exits 1 with nothing changed; a usage error exits 2.

</ManualSection>

<WrapCode>{OUT.mesh_keygen}</WrapCode>

<WrapCode>{OUT.mesh_loose}</WrapCode>

A node signs and seals with the newest key and also accepts the one before it. The previous key is not retired in 0.6.4. No key is printed anywhere; a key is named by its id.

A node is named by its machine’s name (`hostname`, or `COMPUTERNAME` on Windows), and every node needs its own: a node that finds its name taken by a node already running says so and does not join, and exits 3. It broadcasts to find peers and sends to them by unicast; on a network with no broadcast, the `peers` setting names the addresses to announce to. A change too large for one datagram crosses in numbered parts, each answered and resent until the row arrives whole.

<WrapCode>{OUT.mesh_start}</WrapCode>

<WrapCode>{OUT.mesh_parts}</WrapCode>

The mesh is designed and tested for up to 50 nodes. A node away longer than the sunset prints the stash and retrieve commands that catch it up and keeps running; when an awake peer holds the rows, it takes a stash from that peer over the mesh. A node that restarts can be taken by the others for a second machine under its name; that is open as #684 and present in 0.6.3 and 0.6.4.

<ManualSection id="config" note="$XDG_CONFIG_HOME/smugglr/config.toml">

smugglr reads `config.toml` from its config directory: `$XDG_CONFIG_HOME/smugglr`, else `$HOME/.config/smugglr`. The same directory holds smugglr’s memory of each pair of places. A setting smugglr does not read is left alone; a file that is not TOML, or a setting it cannot use, exits 2.

    ],
    [

    ],
    [

Exit 5 above: the record names the stash and retrieve commands to move the rows, with the flags they need. The code comes from what the run did. A crash cannot say whether it wrote, so it exits 4: running again is the next step either way.

<ManualSection id="not-built" note="refused, not built">

--sync-type hub and multi are not built. The CLI says so and exits 2; do not plan around them.

<WrapCode>{OUT.unknown_type}</WrapCode>

- Retiring the previous mesh key. A node accepts the key before the newest with no end date; nothing removes it but taking it out of the key file.
