smugglr 0.5.0. Every usage line below is from `smugglr <command> --help`. Every output block was captured by running that binary against the [Westwind](https://github.com/rafters-studio/smugglr/tree/main/docs/examples/westwind) sample (`docs/examples/westwind/make.sh ./local.db` for the source, `make.sh --empty ./backup.db` for the target), or copied from an example README under `docs/examples/`, which says the same thing about its own blocks. The command sits above each block. Blocks marked stdout omit the tracing on stderr; the split is described under [Output modes](#output-modes).

```
smugglr [OPTIONS] <COMMAND>
```

## Global flags

Global flags go before the subcommand. `smugglr push --dry-run --output json` is an error, and so are `smugglr push -c other.toml` and `smugglr push -v`.

| Flag | Default | Description |
|------|---------|-------------|
| `-c`, `--config <CONFIG>` | `config.toml` | Path to config file. |
| `-v`, `--verbose` | off | Raise the tracing level on stderr from INFO to DEBUG. |
| `-o`, `--output <OUTPUT>` | `text` | Output format: `text` or `json`. |
| `-h`, `--help` | | Print help. |
| `-V`, `--version` | | Print version. |

```
$ smugglr push --dry-run --output json
error: unexpected argument '--output' found

Usage: smugglr push --dry-run

For more information, try '--help'.
```

Exit code 2. The order that works is `smugglr --output json push --dry-run`.

## Output modes

In text mode, stdout carries a summary block and stderr carries timestamped tracing lines, whether or not `-v` is given. The first three stderr lines of a dry-run, from `docs/examples/cli-sqlite-to-sqlite`:

```
2026-08-28T22:08:11.303157Z  INFO Opening local database (read-only): ./local.db
2026-08-28T22:08:11.303347Z  INFO Push mode: local -> SQLite (./backup.db)
2026-08-28T22:08:11.303356Z  INFO Opening local database: ./backup.db
```

`-v` adds DEBUG lines to the same stream. A failure in text mode is one `ERROR` line on stderr and nothing on stdout:

```
$ smugglr snapshot
2026-08-29T02:22:23.141057Z ERROR Error: Configuration error: No [stash] section in config
```

`--output json` silences the tracing and prints one JSON object on stdout, except for `watch`, which prints one object per tick, and `broadcast`, which prints nothing. The shapes are under [JSON output](#json-output).

## push

Push local changes to the remote target (local -> remote). Rows whose content hash already matches the target are not sent.

```
smugglr push [OPTIONS]
```

| Flag | Default | Description |
|------|---------|-------------|
| `-t`, `--table <TABLE>` | all configured tables | Specific table to push. |
| `--dry-run` | off | Show what would be pushed without actually pushing. |

Against a target built with `make.sh --empty`, stdout:

```
$ smugglr push --dry-run

--- Push Summary ---
  customers: 40 rows
  categories: 8 rows
  employees: 9 rows
  order_details: 788 rows
  orders: 320 rows
  products: 20 rows
  shippers: 3 rows
  suppliers: 8 rows

  (dry run - no actual changes made)
```

```
$ smugglr push

--- Push Summary ---
  categories: 8 rows
  suppliers: 8 rows
  shippers: 3 rows
  customers: 40 rows
  employees: 9 rows
  order_details: 788 rows
  orders: 320 rows
  products: 20 rows
```

Same counts. The lines come out in a different order because the summary iterates a map, so compare counts, not line positions. A second push has nothing to move:

```
$ smugglr push

--- Push Summary ---
  No changes to push
```

With `-t`, only that table is diffed. Captured after touching six orders locally:

```
$ smugglr push -t orders --dry-run

--- Push Summary ---
  orders: 6 rows

  (dry run - no actual changes made)
```

```
$ smugglr push -t orders

--- Push Summary ---
  orders: 6 rows
```

A table name that is not in the local database is a configuration error, exit 2. The message lists what is there, including the migration ledger, which sync excludes by default:

```
$ smugglr --output json push --table nope
{"command":"push","status":"error","error":"Invalid table name 'nope'. Available tables: [_smugglr_migrations, categories, customers, employees, order_details, orders, products, shippers, suppliers]","exit_code":2}
```

## diff

Show differences between local and remote. Reads both sides, hashes every row, writes nothing.

```
smugglr diff [OPTIONS]
```

| Flag | Default | Description |
|------|---------|-------------|
| `-t`, `--table <TABLE>` | all configured tables | Specific table to diff. |

Each row lands in one of six buckets: `local_only`, `remote_only`, `local_newer`, `remote_newer`, `content_differs`, `identical`. Captured with six orders edited locally, one shipper edited on the target, and one customer inserted on the target:

```
$ smugglr diff

--- Differences ---

shippers
  1 remote newer, 2 identical
    Remote newer: 019438ea-9036-7221-933c-951305c6e3c1

employees: in sync (9 rows)

customers
  +1 remote only, 40 identical
    Remote only: 019906f0-0000-7000-8000-000000000001

orders
  6 local newer, 314 identical
    Local newer: 019438f2-9941-76b7-a349-38b80ebeedc4, 019438f4-2629-734b-b94a-862cbabaff3c, 019438f0-7f24-7598-8741-725482e34619, 019438f7-0e5c-74f0-9dd5-8e3a657e884d, 019438f0-2b2e-7cbd-9bdc-66548b665d03
      ... and 1 more

products: in sync (20 rows)

suppliers: in sync (8 rows)

categories: in sync (8 rows)

order_details: in sync (788 rows)
```

Text mode prints the first five primary keys per bucket. When nothing differs, every table reports `in sync` and the block ends with `All tables are in sync!`.

## stash

Stash local state to an S3-compatible relay (local -> S3). The relay is a SQLite file at `[stash] url`; `stash` downloads it, upserts local rows into it through the same diff engine as `push`, and uploads it back. On S3 the upload is conditional on the ETag read at download, so two machines stashing at once cannot overwrite each other: the loser exits 4. On a `file://` URL there is no ETag, the put is unconditional, and smugglr warns once.

```
smugglr stash [OPTIONS]
```

| Flag | Default | Description |
|------|---------|-------------|
| `-t`, `--table <TABLE>` | all configured tables | Specific table to stash. |
| `--dry-run` | off | Show what would be stashed without actually uploading. |

From `docs/examples/cli-stash-file-relay`, first stash into a relay that does not exist yet:

```
$ smugglr -c config-a.toml stash

--- Stash Summary ---
  categories: 8 rows
  customers: 40 rows
  employees: 9 rows
  order_details: 788 rows
  orders: 320 rows
  products: 20 rows
  shippers: 3 rows
  suppliers: 8 rows
```

A second stash with no local edits:

```
$ smugglr stash --dry-run

--- Stash Summary ---
  No changes to stash
```

`exclude_columns` is not applied on this path in 0.5.0, so an excluded column still reaches the relay ([smugglr#322](https://github.com/rafters-studio/smugglr/issues/322)).

## snapshot

Create a point-in-time snapshot of the local database. The file is copied to `[stash] url` under `snapshots/<timestamp>-<8 hex>.sqlite` with a `.meta.json` beside it. It is the local file that is copied, never a hosted target, and the copy includes `_smugglr_migrations`. Without a `[stash]` section the command is a configuration error, exit 2. In 0.5.0 the copy is a plain file read, so content still in the WAL is missed ([smugglr#433](https://github.com/rafters-studio/smugglr/issues/433)).

```
smugglr snapshot [OPTIONS]
```

| Flag | Default | Description |
|------|---------|-------------|
| `--dry-run` | off | Show what would be snapshotted without uploading. |

```
$ smugglr snapshot --dry-run

--- Snapshot ---
  Timestamp: 2026-08-29T02:25:34.211Z-c9b1ad78
  Size: 417792 bytes
  _smugglr_migrations: 8 rows
  categories: 8 rows
  customers: 41 rows
  employees: 9 rows
  order_details: 788 rows
  orders: 320 rows
  products: 20 rows
  shippers: 3 rows
  suppliers: 8 rows

  (dry run - no snapshot created)
```

```
$ smugglr snapshot

--- Snapshot ---
  Timestamp: 2026-08-29T02:25:34.226Z-42617419
  Size: 417792 bytes
  _smugglr_migrations: 8 rows
  categories: 8 rows
  customers: 41 rows
  employees: 9 rows
  order_details: 788 rows
  orders: 320 rows
  products: 20 rows
  shippers: 3 rows
  suppliers: 8 rows
```

The dry-run mints a timestamp it does not keep; the eight hex characters are fresh on every run.

## restore

Restore local database from a snapshot. The argument is a timestamp; the snapshot restored is the one at that timestamp or, failing an exact match, the latest one before it. Restore overwrites the local file after running SQLite's `quick_check` on the snapshot. It does not touch a hosted target.

```
smugglr restore [OPTIONS] <TIMESTAMP>
```

| Argument or flag | Description |
|------|-------------|
| `<TIMESTAMP>` | Timestamp of snapshot to restore (exact or closest before). |
| `--dry-run` | Show what would be restored without applying. |

```
$ smugglr restore 2026-08-29T02:25:34.226Z-42617419 --dry-run

--- Restore ---
  Restored snapshot: 2026-08-29T02:25:34.226Z-42617419
  Size: 417792 bytes
  _smugglr_migrations: 8 rows
  categories: 8 rows
  customers: 41 rows
  employees: 9 rows
  order_details: 788 rows
  orders: 320 rows
  products: 20 rows
  shippers: 3 rows
  suppliers: 8 rows

  (dry run - no changes applied)
```

A timestamp between the two snapshots listed above picks the earlier one:

```
$ smugglr restore 2026-08-29T02:25:34.230Z

--- Restore ---
  Restored snapshot: 2026-08-29T02:25:34.226Z-42617419
  Size: 417792 bytes
  _smugglr_migrations: 8 rows
  categories: 8 rows
  customers: 41 rows
  employees: 9 rows
  order_details: 788 rows
  orders: 320 rows
  products: 20 rows
  shippers: 3 rows
  suppliers: 8 rows
```

A timestamp earlier than every snapshot is a stash error, exit 1, not 5:

```
$ smugglr --output json restore 2020-01-01T00:00:00Z
{"command":"restore","status":"error","error":"Stash error: No snapshot found at or before 2020-01-01T00:00:00Z. Earliest available: 2026-08-29T02:25:34.226Z-42617419","exit_code":1}
```

The comparison is on the string, not a parsed date. In this session's run, `smugglr restore banana` restored the latest snapshot and exited 0, because `banana` sorts after every snapshot name. Pass a timestamp copied from `smugglr snapshots`, and run `--dry-run` first: the dry-run names the snapshot the real run would pick.

## watch

Watch for changes and sync periodically (daemon mode). Every tick is a full `sync` against the configured target. The daemon takes a `.smugglr.pid` lock in the working directory, and after each tick it writes `last_sync` into the config file, where it gates nothing.

```
smugglr watch [OPTIONS]
```

| Flag | Default | Description |
|------|---------|-------------|
| `-i`, `--interval <INTERVAL>` | `30` | Sync interval in seconds. |
| `--dry-run` | off | Show what would be synced without actually syncing. |

In text mode `watch` prints nothing to stdout. Everything it says is tracing on stderr. Captured with a one-second interval after editing three shippers locally, then stopped with Ctrl+C; the lock, open, and per-table diff lines are cut, and timestamps and ANSI color stripped:

```
$ smugglr watch -i 1
 INFO Starting watch daemon (interval: 1s, dry_run: false)
 INFO Pushing 3 rows to table: shippers (dry_run=false)
 INFO Upserted 3 rows into shippers
 INFO Tick #1: 3 pushed, 0 pulled across 8 tables
 INFO Tick #2: no changes
 INFO Received shutdown signal. Stopping watch daemon.
 INFO Watch daemon stopped after 2 ticks
 INFO Released PID lock: .smugglr.pid
```

With `--dry-run` the daemon opens both databases read-only for its whole life, so no tick can write, and each tick line says so (same cuts):

```
$ smugglr watch -i 1 --dry-run
 INFO Starting watch daemon (interval: 1s, dry_run: true)
 INFO Pushing 3 rows to table: shippers (dry_run=true)
 INFO Tick #1: 3 pushed, 0 pulled across 8 tables (dry run - no actual changes made)
 INFO Tick #2: 3 pushed, 0 pulled across 8 tables (dry run - no actual changes made)
 INFO Received shutdown signal. Stopping watch daemon.
 INFO Watch daemon stopped after 2 ticks
```

The daemon handles SIGINT only. Ctrl+C finishes the current tick, logs the shutdown, and releases the lock. SIGTERM is not handled: in this session's run `kill -TERM` ended the process with status 143 and no shutdown lines, and the next start logged `Removing stale PID file`. Under systemd or a supervisor, send SIGINT.

With `--output json`, stderr is silent and stdout carries one line per tick; see [Watch](#watch-jsonl) under JSON output.

## broadcast

LAN broadcast sync with peer discovery. Every node multicasts a `primary_key -> content_hash` digest of its tables each interval and requests the rows it lacks; every listener applies answers idempotently. Configuration is the `[broadcast]` section: `secret`, `port` (default 31337), `interval_secs` (default 30), `instance_id` (default hostname), `conflict_resolution`, `ordering_columns`. With `secret` set, every datagram is XChaCha20-Poly1305. Without it the node runs in the clear, accepts any well-formed datagram from the subnet, and warns once at start. Deletes do not replicate on any path in 0.5.0.

```
smugglr broadcast [OPTIONS]
```

| Flag | Default | Description |
|------|---------|-------------|
| `-p`, `--port <PORT>` | `[broadcast] port` | Override broadcast port. |
| `-i`, `--interval <INTERVAL>` | `[broadcast] interval_secs` | Sync interval in seconds. |
| `--once` | off | Run a single sync cycle and exit. |
| `--dry-run` | off | Show what would sync without applying. |

`broadcast` writes nothing to stdout in either output mode; `--output json broadcast` prints nothing on stdout or stderr. In text mode everything it says is on stderr. From `docs/examples/cli-lan-broadcast`, one node (timestamps and ANSI color stripped):

```
$ smugglr broadcast
 INFO Acquired PID lock: .smugglr-broadcast.pid (PID 30382)
 INFO Starting masterless multicast sync (group 239.255.43.21, port 31999, interval 2s, instance peer-d, dry_run false)
 INFO Opening local database: d.db
 INFO Heartbeat #1: multicast 1 digest datagram(s)
 INFO Heartbeat #2: multicast 1 digest datagram(s)
```

`--once` sends one heartbeat, waits briefly for answers, and exits. Captured against Westwind on one host:

```
$ smugglr broadcast --once
 INFO Acquired PID lock: .smugglr-broadcast.pid (PID 98814)
 INFO Starting masterless multicast sync (group 239.255.43.21, port 31998, interval 2s, instance Puck.local, dry_run false)
 INFO Opening local database: ./node.db
 INFO Single heartbeat sent; converging briefly...
 INFO Single cycle complete, exiting
 INFO Released PID lock: .smugglr-broadcast.pid
```

```
$ smugglr broadcast --once --dry-run -p 31997
 INFO Acquired PID lock: .smugglr-broadcast.pid (PID 99173)
 INFO Starting masterless multicast sync (group 239.255.43.21, port 31997, interval 2s, instance Puck.local, dry_run true)
 INFO Opening local database: ./node.db
 INFO Dry run: would multicast 112 digest datagram(s); not sending, not applying
 INFO Released PID lock: .smugglr-broadcast.pid
```

Two nodes on one host need distinct `instance_id` values and separate working directories, because the PID lock is per directory and a node drops datagrams carrying its own id. On macOS the application firewall silently drops inbound multicast for an unsigned binary. Multicast does not cross routers; for machines on different networks, put them on one tunnel.

## migrate new

Scaffold a new migration manifest from a Rails-style column spec and print it to stdout. `migrate` runs before any config is loaded, so it neither reads nor needs `config.toml`.

```
smugglr migrate new <NAME> [COLUMN]...
```

| Argument | Description |
|------|-------------|
| `<NAME>` | Migration name (e.g. `create_contacts`); the table is derived from it. |
| `[COLUMN]...` | Column specs: `name[:type][:modifier...]` (type defaults to text). |

In 0.5.0 the name must be `create_<table>`; the alter form is deferred:

```
$ smugglr --output json migrate new add_x a:int
{"command":"migrate","status":"error","error":"Configuration error: unsupported migration name 'add_x': 0.5.0 supports only the create-table form 'create_<table>' (the alter form is deferred)","exit_code":2}
```

From `docs/examples/cli-migrate`, the scaffold and the manifest it prints. Keys default to `TEXT`; `notnull` satisfies the first-run check that wants a declared key non-nullable:

```
$ smugglr migrate new create_bribes id:pk:notnull harbormaster:text amount:int paid_at:int > migrations/create_bribes.json
```

```json
{
  "manifest": {
    "version": 1,
    "target_schema": "",
    "up": [
      {
        "op": {
          "op": "create_table",
          "table": "bribes",
          "columns": [
            { "name": "id", "kind": "text", "constraints": [ { "constraint": "pk" }, { "constraint": "not_null" } ] },
            { "name": "harbormaster", "kind": "text" },
            { "name": "amount", "kind": "int" },
            { "name": "paid_at", "kind": "int" }
          ],
          "without_rowid": false
        },
        "op_class": "additive"
      }
    ],
    "down": [
      { "op": { "op": "drop_table", "table": "bribes" }, "op_class": "destructive" }
    ],
    "flags": { "destructive": false, "hash_rewriting": false }
  },
  "checksum": "62f1d23e0c3b34222075d7f99ed090c4971710642a5201af5ad51bdb99d90148"
}
```

Each op carries an `op_class`, additive or destructive, and the checksum covers the whole manifest. `--output json` changes nothing here; the manifest is already the output. `migrate new` does not yet refuse an explicit `int:pk` ([smugglr#427](https://github.com/rafters-studio/smugglr/issues/427)), and there is no `int -> UUIDv7` conversion for an existing table ([smugglr#280](https://github.com/rafters-studio/smugglr/issues/280)).

## migrate apply

Apply a migration manifest to a local SQLite database. The version is assigned by the ledger, `_smugglr_migrations`, inside the migrated database: the migration lands as `current_version + 1`, claimed before the first op runs and settled to `success` or `failed` after. A manifest whose checksum is already in the ledger is refused before any op runs.

```
smugglr migrate apply [OPTIONS] --db <PATH> <MANIFEST>
```

| Argument or flag | Description |
|------|-------------|
| `<MANIFEST>` | Path to the checksummed manifest JSON (as emitted by `migrate new`). |
| `--db <PATH>` | The local SQLite database to apply against. Required; `migrate` never reads `config.toml`, so a migration applies where you point it. |
| `--paranoid` | Snapshot the database before applying. In 0.5.0 this warns and applies without a snapshot ([smugglr#289](https://github.com/rafters-studio/smugglr/issues/289)). |

The database must exist; `migrate apply` opens read-write without create:

```
$ smugglr --output json migrate apply migrations/create_bribes.json --db ./nope.db
{"command":"migrate","status":"error","error":"Local database error: unable to open database file: ./nope.db","exit_code":1}
```

From `docs/examples/cli-migrate`. Westwind was built by eight applies, so this one lands as v9, and the second attempt is answered by the ledger:

```
$ smugglr migrate apply migrations/create_bribes.json --db ./westwind.db
Applied migration v9 (1 op) -- checksum 62f1d23e0c3b34222075d7f99ed090c4971710642a5201af5ad51bdb99d90148
```

```
$ smugglr migrate apply migrations/create_bribes.json --db ./westwind.db
Migration v9 is already applied -- nothing to do
```

`--paranoid` on the same apply, stderr then stdout:

```
$ smugglr migrate apply migrations/create_bribes.json --db ./westwind.db --paranoid
 WARN --paranoid requested but the pre-migration snapshot is not implemented until #289; applying without a parachute version=9
Applied migration v9 (1 op) -- checksum 62f1d23e0c3b34222075d7f99ed090c4971710642a5201af5ad51bdb99d90148
```

What 0.5.0 does not do: there is no reverse subcommand, though the `down` list is written into every manifest; `--paranoid` warns instead of snapshotting ([#289](https://github.com/rafters-studio/smugglr/issues/289)); the D1, Turso, and rqlite dialects generate statements but refuse to execute them, so `--db` is a local SQLite file only ([#291](https://github.com/rafters-studio/smugglr/issues/291)); and `migrate new` accepts only `create_<table>` names.

## Exit codes

From `smugglr --help`:

| Code | Meaning |
|------|---------|
| `0` | success |
| `1` | general error |
| `2` | configuration error (fix the config, do not retry) |
| `3` | connection/network error (transient, safe to retry) |
| `4` | conflict (needs a human decision -- pick a conflict_resolution) |
| `5` | target not found (database missing or API unreachable) |

Codes map from the error, not from the command, so there is no per-command set. The same unreadable target file is exit 0 under `status`, which reports it, and exit 1 under `push`, which needs it. A missing config file, an unset `${VAR}` in the config, a `--table` that does not exist, a global flag after the subcommand, and a `migrate new` name that is not `create_<table>` are all exit 2. A restore with no snapshot at or before the timestamp is exit 1. An S3 ETag mismatch on `stash` is exit 4; row-level conflicts on `push`, `pull`, and `sync` are resolved by `conflict_resolution` and never raise it. A plugin failure folds into exit 1; there is no plugin-specific code, and there is no code above 5.

```bash
smugglr --output json stash
case $? in
  0) echo "done" ;;
  2) echo "fix your config" && exit 1 ;;
  3) echo "network issue, retrying" && sleep 5 && smugglr --output json stash ;;
  4) echo "relay changed under us, retrieve first" && smugglr retrieve && smugglr stash ;;
  *) echo "unexpected: $?" && exit 1 ;;
esac
```

## JSON output

`--output json` before the subcommand. One object on stdout, tracing silenced. Every object carries `command` and `status`; `status` is `ok`, `dry_run`, or `error`. The `exit_code` field appears on `dry_run` and `error` objects only.

### push, pull, sync, stash, retrieve

Counts per table, and only for tables that moved rows. A table entry carries `rows_pushed` or `rows_pulled` when non-zero; an empty `tables` is a no-op. From `docs/examples/cli-sqlite-to-sqlite`, after touching six orders locally:

```
$ smugglr --output json push
{"command":"push","status":"ok","tables":[{"name":"orders","rows_pushed":6}]}

$ smugglr --output json push
{"command":"push","status":"ok","tables":[]}
```

Captured with six orders edited locally, one shipper edited and one customer inserted on the target:

```
$ smugglr --output json sync
{"command":"sync","status":"ok","tables":[{"name":"customers","rows_pulled":1},{"name":"shippers","rows_pulled":1},{"name":"orders","rows_pushed":6}]}
```

```
$ smugglr --output json pull
{"command":"pull","status":"ok","tables":[{"name":"products","rows_pulled":1}]}
```

`stash` reports its uploads as `rows_pushed` and `retrieve` its applied rows as `rows_pulled`. First stash into an empty `file://` relay:

```
$ smugglr --output json stash
{"command":"stash","status":"ok","tables":[{"name":"categories","rows_pushed":8},{"name":"customers","rows_pushed":41},{"name":"employees","rows_pushed":9},{"name":"order_details","rows_pushed":788},{"name":"orders","rows_pushed":320},{"name":"products","rows_pushed":20},{"name":"shippers","rows_pushed":3},{"name":"suppliers","rows_pushed":8}]}
```

A stash or retrieve that finds the relay already matching reports `"tables":[]`, the same no-op shape as push.

### Dry-run

`status` is `dry_run`. Every configured table appears, each with all six bucket counts plus `rows_to_push` and `rows_to_pull`, and the object closes with both totals and `exit_code`. The shape is the same for `push`, `pull`, `sync`, `stash`, and `retrieve`; for a push the pull counts are zero, for a pull the push counts are zero, for a sync both are populated. Captured after touching six orders locally:

```
$ smugglr --output json push --dry-run -t orders
{"command":"push","status":"dry_run","tables":[{"name":"orders","local_only":0,"remote_only":0,"local_newer":6,"remote_newer":0,"content_differs":0,"identical":314,"rows_to_push":6,"rows_to_pull":0}],"total_rows_to_push":6,"total_rows_to_pull":0,"exit_code":0}
```

Without `-t`, all eight Westwind tables are listed, the seven unchanged ones with zeros in every bucket but `identical`; the full object is in `docs/examples/cli-sqlite-to-sqlite`. The six rows are `local_newer`, not `content_differs`, because the edit also bumped `updated_at`; an edit that leaves the timestamp alone lands in `content_differs` and is resolved by `conflict_resolution`.

### diff

Five buckets as arrays of primary keys, and `identical_count` as a number. Every configured table appears, including the ones in sync. Captured with six orders edited locally:

```
$ smugglr --output json diff -t orders
{"command":"diff","status":"ok","tables":[{"name":"orders","local_only":[],"remote_only":[],"local_newer":["019438f7-0e5c-74f0-9dd5-8e3a657e884d","019438f4-2629-734b-b94a-862cbabaff3c","019438f0-7f24-7598-8741-725482e34619","019438f0-2b2e-7cbd-9bdc-66548b665d03","019438eb-c186-7bc5-ab0d-0b0e43b34cfb","019438f2-9941-76b7-a349-38b80ebeedc4"],"remote_newer":[],"content_differs":[],"identical_count":314}]}
```

```
$ smugglr --output json diff -t customers
{"command":"diff","status":"ok","tables":[{"name":"customers","local_only":[],"remote_only":["019906f0-0000-7000-8000-000000000001"],"local_newer":[],"remote_newer":[],"content_differs":[],"identical_count":40}]}
```

Text mode truncates each bucket after five keys; JSON does not.

### Watch (JSONL)

One line per tick, each with a `tick` counter and the same `tables` shape as `sync`. Stderr is silent. Captured with a one-second interval; three shippers were edited locally between ticks 3 and 4, and the run was stopped with Ctrl+C after tick 5:

```
$ smugglr --output json watch -i 1
{"command":"watch","tick":1,"status":"ok","tables":[]}
{"command":"watch","tick":2,"status":"ok","tables":[]}
{"command":"watch","tick":3,"status":"ok","tables":[]}
{"command":"watch","tick":4,"status":"ok","tables":[{"name":"shippers","rows_pushed":3}]}
{"command":"watch","tick":5,"status":"ok","tables":[]}
```

Parse line by line. No final object is written on shutdown.

### migrate apply

`version` is the ledger's assignment, `election` is `won` for an apply that ran and `already_applied` for one the ledger refused, and `ops_applied` counts the ops that ran.

```
$ smugglr --output json migrate apply migrations/create_bribes.json --db ./fresh.db
{"command":"migrate apply","status":"ok","version":9,"checksum":"62f1d23e0c3b34222075d7f99ed090c4971710642a5201af5ad51bdb99d90148","election":"won","ops_applied":1,"destructive":false,"hash_rewriting":false,"preimage_captured":false}
```

```
$ smugglr --output json migrate apply migrations/create_bribes.json --db ./fresh.db
{"command":"migrate apply","status":"ok","version":9,"checksum":"62f1d23e0c3b34222075d7f99ed090c4971710642a5201af5ad51bdb99d90148","election":"already_applied","ops_applied":0,"destructive":false,"hash_rewriting":false,"preimage_captured":false}
```

`preimage_captured` is false in 0.5.0 on every run; it will report the `--paranoid` snapshot once [smugglr#289](https://github.com/rafters-studio/smugglr/issues/289) lands.

### Error

`error` is the message, `exit_code` is the process exit status. The `command` field names the subcommand, or `migrate` for either migrate subcommand.

```
$ smugglr -c nope.toml --output json status
{"command":"status","status":"error","error":"Config file not found: nope.toml","exit_code":2}
```

```
$ smugglr --output json push
{"command":"push","status":"error","error":"Local database error: unable to open database file: ./missing-dir/backup.db","exit_code":1}
```

```
$ smugglr --output json status
{"command":"status","status":"error","error":"Config references unset environment variable ${SMUGGLR_NOPE}","exit_code":2}
```

The exit code is the scripting contract; the object repeats it so a consumer that swallowed the status still has it.
