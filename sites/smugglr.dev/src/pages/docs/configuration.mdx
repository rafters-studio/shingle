smugglr reads `config.toml` from the working directory, or the file named by `-c <path>` (`--config`). `-c` is a global flag and goes before the subcommand. Every key and default on this page was read from `smugglr-core`'s `config.rs` and `broadcast.rs` at 0.5.0, and every config block is copied from a file under `docs/examples/` in the smugglr repository; the example is named above each block.

---

## Quick Start

The shortest path is two local SQLite files. Nothing leaves the machine, no credentials, no plugin. From `docs/examples/cli-sqlite-to-sqlite/config.example.toml`:

```toml
local_db = "./local.db"

[target]
type = "sqlite"
database = "./backup.db"

[sync]
tables = []
timestamp_column = "updated_at"
conflict_resolution = "local_wins"
```

Then a dry-run, then a push. Captured from that example against the Westwind sample on 2026-08-28; stdout only, the `INFO` tracing goes to stderr.

```
$ smugglr push --dry-run
--- Push Summary ---
  order_details: 788 rows
  suppliers: 8 rows
  employees: 9 rows
  shippers: 3 rows
  categories: 8 rows
  products: 20 rows
  customers: 40 rows
  orders: 320 rows

  (dry run - no actual changes made)
```


## Sections

A config has one top-level key and up to four tables.

| Section | Required | Purpose |
|---------|----------|---------|
| `local_db` | yes, or auto-detected | The SQLite file smugglr reads and writes. |
| `[target]` | for push, pull, sync, diff, status, watch | Where rows go, or come from. |
| `[sync]` | no | Which tables, which columns, which side wins, batch and retry limits. |
| `[stash]` | for stash, retrieve, snapshot, snapshots, restore | The relay: a SQLite file in an object store. |
| `[broadcast]` | for broadcast | LAN multicast sync. |

### local_db

Path to the local SQLite database. Relative paths resolve from the working directory, not from the config file. If the key is absent, smugglr looks in `.wrangler/state/v3/d1/miniflare-D1DatabaseObject/` and takes the largest non-empty `.sqlite` file; with no such directory the load fails with exit 2.

---

### [target]

Three target types. `type` selects the variant and the other keys depend on it. Target resolution happens at command dispatch, so `broadcast`, `stash`, `retrieve`, `snapshot`, and `restore` run without a `[target]` at all.

#### Target type: `sqlite`

A second SQLite file. This is the only target the `smugglr` binary reaches on its own; every other target needs the separate `smugglr-http-sql` binary.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `type` | string | none | `"sqlite"` |
| `database` | string | none | Path to the `.db` file. Relative paths resolve from the working directory, not from the config file. |

#### Target type: `plugin`

Delegates the connection to a plugin binary. The one plugin smugglr ships is `smugglr-http-sql`, which reaches every hosted backend through a profile. It is a separate binary, installed with `cargo install smugglr-http-sql` or from the release archive, which carries it beside `smugglr` from 0.5.1. Without it every hosted target fails with `Plugin 'http-sql' not found`.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `type` | string | none | `"plugin"` |
| `name` | string | none | Plugin name. smugglr looks for `~/.smugglr/plugins/smugglr-<name>`, then `smugglr-<name>` on `$PATH`. For the shipped plugin the value is `"http-sql"`. `name = "turso"` is a mistake and fails with `Plugin 'turso' not found`. |
| `path` | string | none | Explicit path to a plugin binary. When both are set, `path` wins. One of `name` or `path` is required. |
| `[target.config]` | table | `{}` | String keys handed to the plugin's `initialize`. |

The keys `smugglr-http-sql` reads from `[target.config]`:

| Key | Default | Description |
|-----|---------|-------------|
| `profile` | `"generic"` | The backend's request and response shape. One of `d1`, `turso`, `rqlite`, `datasette`, `sqlite-cloud`, `starbasedb`, `generic`, `http-sql`; see the [Plugin Guide](/docs/plugin-guide/) for the aliases. An unknown name fails with `unknown profile: <name>`. |
| `url` | none, required | The literal endpoint the plugin POSTs SQL to. Nothing is parsed, rewritten, or templated. Missing it fails with `missing config: url`. |
| `auth_token` | `""` | Sent as `Authorization: Bearer <token>` on every profile except `rqlite`, which sends it as the basic-auth username. Empty means no `Authorization` header. |

From `docs/examples/cli-http-sql-turso/config.example.toml`:

```toml
local_db = "./local.db"

[target]
type = "plugin"
name = "http-sql"

[target.config]
profile = "turso"
url = "https://my-db.turso.io"
auth_token = "${TURSO_TOKEN}"
```

Swap `profile` and `url` for rqlite, Datasette, SQLite Cloud, StarbaseDB, or a generic `{sql, params}` endpoint. The commands do not change.

#### Target type: `d1`

Cloudflare D1. This shape parses, and in 0.5.0 it does not reach D1. Three independent defects stop it: the core hands the plugin `account_id`, `database_id`, and `api_token`, while the plugin needs a `url` and reads the token from `auth_token` ([smugglr#429](https://github.com/rafters-studio/smugglr/issues/429)); `cargo install smugglr` and the 0.5.0 archive ship no plugin binary ([smugglr#430](https://github.com/rafters-studio/smugglr/issues/430), fixed for 0.5.1); and the `d1` profile reads its rows as its column list, so table discovery collapses ([smugglr#436](https://github.com/rafters-studio/smugglr/issues/436)). The shape below is the one the fixes will honor. No output is shown because none was produced.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `type` | string | none | `"d1"` |
| `account_id` | string | none | Cloudflare account ID. |
| `database_id` | string | none | D1 database UUID. |
| `api_token` | string | none | Cloudflare API token with D1 scope. |
| `url` | string | absent | Custom endpoint, for a Durable Objects bridge or a proxy. Only forwarded to the plugin when set; `url = ""` forwards an empty string, and the plugin posts to an empty endpoint. |

At runtime `type = "d1"` becomes a `plugin` target with `profile = "d1"`, so it needs `smugglr-http-sql` like every other hosted backend. From `docs/examples/cli-d1-sync/config.example.toml`:

```toml
local_db = "./app.sqlite"

[target]
type = "d1"
account_id = "your-32-char-account-id"
database_id = "your-d1-database-uuid"
api_token = "${SMUGGLR_D1_TOKEN}"
```

#### Legacy flat fields

Three top-level keys from before `[target]` existed still parse, and map to `type = "d1"`, so they share its three defects. From the root `config.example.toml`:

```toml
cloudflare_account_id = "your-32-char-account-id"
cloudflare_api_token = "your-api-token-with-d1-permissions"
database_id = "your-d1-database-uuid"
```

A `[target]` section takes precedence when both are present. Use `[target]` in new configs.

### [sync]

Which tables move, which columns are hashed and sent, which side wins, and how writes are batched. Every key has a default, so the whole section is optional.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `tables` | array of strings | `[]` | Tables to sync. Empty means every table not excluded. Names match exactly. |
| `exclude_tables` | array of strings | `["sqlite_sequence", "_cf_KV", "__drizzle_migrations", "_smugglr_migrations"]` | Tables never synced. Names match exactly; a glob excludes nothing. Setting the key replaces the default list, so repeat the four names if you still want them. `_smugglr_migrations` is the `migrate` ledger. |
| `exclude_columns` | array of strings | `[]` | Columns left out of the content hash on every path, and out of the transferred row on directional push and pull only. Glob: `*` at the start, the end, or both (`*_embedding`, `cache_*`, `*embed*`); no `?`, no character classes. On `stash`, `retrieve`, and a multicast peer's row request the column still travels ([smugglr#322](https://github.com/rafters-studio/smugglr/issues/322)). Do not use it for confidentiality. |
| `converge_columns` | array of strings | `[]` | Columns left out of the content hash but still transferred. Same glob syntax. For a table with a match here, a hash match no longer means identical: the diff compares `timestamp_column` and takes the newer row. A pattern that appears in both lists, or matches the other list's pattern text, is refused at load with exit 2. |
| `timestamp_column` | string | `"updated_at"` | The column that decides which row is newer under `newer_wins`, and classifies rows into `local_newer` and `remote_newer`. |
| `conflict_resolution` | string | `"local_wins"` | Which side wins when both hold a row with the same primary key. See the table below. |
| `duplicate_pk` | string | `"refuse"` | What to do when two rows in one table on one side render the same primary key. `refuse` stops before any write, naming the key, the table, and both content hashes. `warn` logs it and lets the later row evict the earlier one from the diff; the evicted row is invisible to that sync. |
| `batch_size` | integer | `100` | Rows per write batch. |
| `max_statement_bytes` | integer | `92160` | Bytes per SQL statement. D1's limit is 100 KB; 92160 (90 KiB) is the safety margin. |
| `max_retries` | integer | `5` | Retries on a transient write failure, capped at 100. |
| `initial_retry_delay_ms` | integer | `100` | Delay before the first retry. |
| `max_retry_delay_ms` | integer | `30000` | Ceiling on the delay between retries. |
| `backoff_multiplier` | float | `2.0` | Factor applied to the delay after each retry; values below 1.0 are raised to 1.0. |

Two facts about this section that the keys do not show. `smugglr watch` writes a `last_sync` line under `[sync]` after each tick; it is informational and gates nothing. And the retry keys describe an engine that never runs against a hosted backend in 0.5.0, because `smugglr-http-sql` reports every 429 and 5xx as permanent ([smugglr#432](https://github.com/rafters-studio/smugglr/issues/432)); a rate limit ends the push on the first response with exit 1.

#### Conflict resolution

Four names. On directional push and pull, one local row meets one remote row and every policy is deterministic. Under `[broadcast]` the same names have a second property, convergence, covered in that section.

| Policy | Behavior on push, pull, sync |
|--------|------------------------------|
| `local_wins` | The local row overwrites the remote one. Default. |
| `remote_wins` | The remote row overwrites the local one. |
| `newer_wins` | The row with the greater `timestamp_column` wins. A row pair with different content and no comparable timestamp is skipped in both directions, with one warning per table. |
| `uuid_v7_wins` | In 0.5.0 this is `newer_wins` with a different warning. No code reads the timestamp inside the key; the row is ordered on `timestamp_column` ([smugglr#431](https://github.com/rafters-studio/smugglr/issues/431)). |

### [stash]

The relay for machines that cannot reach each other: a SQLite file in an object store. `smugglr stash` downloads it, upserts local rows into it, and uploads it back; `smugglr retrieve` downloads it and upserts its rows into the local database. Both run the same diff engine as push and pull, row by row; the local file is never replaced wholesale. `snapshot`, `snapshots`, and `restore` use the same store, under `snapshots/`.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `url` | string | none, required | The relay file. `s3://bucket/path/relay.sqlite` for S3-compatible storage, `file:///path/relay.sqlite` for the local filesystem. The URL names a file, not a prefix. |
| `access_key_id` | string | none | S3 access key. Optional when the environment or an instance role supplies credentials. |
| `secret_access_key` | string | none | S3 secret key. |
| `region` | string | `"us-east-1"` | S3 region. `"auto"` for R2. |
| `endpoint` | string | none | Custom S3-compatible endpoint. Required for R2, MinIO, Backblaze B2, and other non-AWS stores. |

On S3 the upload is conditional on the ETag read at download, so two machines stashing at once cannot overwrite each other; the loser exits 4 and runs again. On `file://` there is no ETag, the put is unconditional, and smugglr warns once. `exclude_columns` is not applied on this path ([smugglr#322](https://github.com/rafters-studio/smugglr/issues/322)).

From `docs/examples/cli-stash-file-relay/config.example.toml`:

```toml
local_db = "./machine-a.db"

[stash]
url = "file:///tmp/smugglr-relay/relay.sqlite"

[sync]
timestamp_column = "updated_at"
conflict_resolution = "newer_wins"
```

Captured from that example on 2026-08-28, machine A then machine B:


### [broadcast]

LAN sync over UDP multicast, group `239.255.43.21`. Every node multicasts a primary-key-to-content-hash digest of its tables each interval and asks for the rows it lacks; whoever holds them answers on the same group. No coordinator, no relay, no ACKs. Applying a row twice is a no-op, so a lost datagram is covered by the next heartbeat.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `port` | integer | `31337` | UDP port. The same on every node. |
| `interval_secs` | integer | `30` | Seconds between heartbeats. A peer unheard for three intervals is pruned. |
| `instance_id` | string | hostname | This node's identity. A node drops every datagram carrying its own id, so two nodes on one host need distinct values. |
| `secret` | string | absent | 64 hex characters, a 256-bit key. When set, every datagram is XChaCha20-Poly1305 with a fresh nonce, and a node with a different key sees only ciphertext. When absent the node still runs, unencrypted and unauthenticated, accepting any well-formed datagram on the subnet, and warns once at bind. A keyed node and a keyless node cannot sync. |
| `conflict_resolution` | string | `"remote_wins"` | Which row wins when a received row meets a local row with the same primary key. Scoped to this section; it is deliberately not read from `[sync]`, whose default of `local_wins` would keep the local row on every contended key. |
| `ordering_columns` | array of strings | `[]` | Columns compared, as a maximum across whichever the table has, under `newer_wins`. Empty falls back to `[sync].timestamp_column`. |

The policy names mean more here than on the directional path, because N peers apply independently and nothing coordinates them. `remote_wins` is last-received-wins: an unconditional `INSERT OR REPLACE`, evaluated at each node, so two peers that receive the same two writes in different orders keep different rows for that key, permanently, with no error. `local_wins` lowers to `ON CONFLICT DO NOTHING`, so every node keeps its own row on a contended key and the key stays divergent by construction. `newer_wins` is the only total order and the only policy under which the mesh converges; it is apply-side and not negotiated, so every peer must set it. `uuid_v7_wins` degenerates to `newer_wins`, because two rows with the same primary key carry the same UUID. Deletes do not replicate on any path in 0.5.0 ([smugglr#311](https://github.com/rafters-studio/smugglr/issues/311)); model a delete as a `deleted_at` column and put it in `ordering_columns`.

The hash-exclusion lists are local config and never negotiated either. Two peers with different `exclude_columns` or `converge_columns` for the same table hash the same row over different column sets, and the mesh never quiesces. Roll a change to those lists out to every peer.

From `docs/examples/cli-lan-broadcast/config.example.toml`, comments removed:

```toml
local_db = "./node.db"

[sync]
tables = []
timestamp_column = "updated_at"

[broadcast]
secret = "REPLACE_WITH_OUTPUT_OF_openssl_rand_-hex_32"
port = 31337
interval_secs = 5
conflict_resolution = "newer_wins"
ordering_columns = ["updated_at"]
```

Generate the key once and distribute it out of band:

```sh
openssl rand -hex 32
```

`broadcast` prints nothing to stdout in text mode; everything it says is on stderr. Captured from one node on 2026-08-28, timestamps and color stripped:

```
$ smugglr broadcast
 INFO Acquired PID lock: .smugglr-broadcast.pid (PID 30382)
 INFO Starting masterless multicast sync (group 239.255.43.21, port 31999, interval 2s, instance peer-d, dry_run false)
 INFO Opening local database: d.db
 INFO Heartbeat #1: multicast 1 digest datagram(s)
 INFO Heartbeat #2: multicast 1 digest datagram(s)
```

Multicast does not cross routers or VLANs. For machines on different networks, put them on one subnet with Tailscale, WireGuard, or ZeroTier. On macOS the application firewall silently drops inbound multicast for a binary it has not been told about.

## Environment Variables

Every string value in the file accepts `${VAR}`. `${VAR:-default}` supplies a fallback, and `$$` is a literal `$`. Expansion runs after the TOML parse, on string values only, so a token can never inject structure and never reaches a parser error message. An unset variable with no default is a hard error, exit 2, that names the variable; a blank credential is never sent silently.

From `docs/examples/cli-http-sql-turso/config.example.toml`:

```toml
[target]
type = "plugin"
name = "http-sql"

[target.config]
profile = "turso"
url = "https://my-db.turso.io"
auth_token = "${TURSO_TOKEN}"
```

The file can be committed; the token lives in the environment.
