<Section id="patterns" title="Six Usage Patterns.">
    <P>One engine, six shapes. Pick the one that matches where your data needs to go.</P>

    <FeatureBlock title="Direct sync.">
        <P>Push, pull, or full bidirectional sync between a local SQLite file and a remote target. The everyday case.</P>
        <Codeblock>{`smugglr push            # local -> remote
smugglr pull            # remote -> local
smugglr sync            # both directions, with conflict strategy`}</Codeblock>
    </FeatureBlock>

    <FeatureBlock title="Watch daemon.">
        <P>Background sync on a fixed interval. Set it and forget it. Emits JSONL per tick for pipelines.</P>
        <Codeblock>{`smugglr watch --interval 30`}</Codeblock>
    </FeatureBlock>

    <FeatureBlock title="Fan-out (LAN broadcast).">
        <P>Encrypted UDP datagrams across a subnet. The encryption key is the membership token. No auth handshake, no coordinator. IoT-shaped.</P>
        <Codeblock>{`smugglr broadcast --interval 10`}</Codeblock>
    </FeatureBlock>

    <FeatureBlock title="Stash and retrieve.">
        <P>S3-compatible object storage as a relay between machines that cannot see each other directly. Works with R2, MinIO, or any S3 endpoint.</P>
        <Codeblock>{`smugglr stash               # upload to relay
smugglr retrieve            # download to local`}</Codeblock>
    </FeatureBlock>

    <FeatureBlock title="Snapshot and restore.">
        <P>Point-in-time backup to the relay. Portable across backends: snapshot from D1, restore to Turso.</P>
        <Codeblock>{`smugglr snapshot
smugglr snapshots
smugglr restore 2026-04-03T09:15:44Z`}</Codeblock>
    </FeatureBlock>

    <FeatureBlock title="Diff.">
        <P>Read-only comparison. Moves nothing. Shows what push, pull, or sync would do.</P>
        <Codeblock>{`smugglr diff`}</Codeblock>
    </FeatureBlock>
</Section>
