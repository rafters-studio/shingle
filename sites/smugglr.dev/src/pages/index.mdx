<Section id="show" title="Show it running." tint>
    <P>A short TOML file, one dry-run, one push. The whole product in thirty seconds.</P>

    <Codeblock>{`[source]
path = "./local.db"

[target]
type = "d1"
database = "my-db"
account_id = "abc123"
api_token = "..."`}</Codeblock>

    <Codeblock>{`$ smugglr push --dry-run
Comparing source and target...
  abilities        47 new, 0 changed, 0 missing
  missions          3 new, 1 changed, 0 missing
  characters        0 new, 0 changed, 0 missing
51 rows to write. 0 conflicts. No data moved.`}</Codeblock>

    <Codeblock>{`$ smugglr push
  abilities        47 inserted
  missions          3 inserted, 1 updated
  characters        no change
51 rows written in 2.3s. exit 0.`}</Codeblock>

    <P>The dry-run writes nothing. The push writes exactly what the dry-run described. Same output, same counts. No surprises.</P>

<Section id="moat" title="One plugin, any LIKE backend.">
    <P>Every remote target smugglr reaches goes through one plugin, <code>smugglr-http-sql</code>. Each backend is a profile, defined in TOML. Swapping targets is a config change, not a fork, not a recompile.</P>

    <P>Six profiles ship today:</P>

    <Codeblock>{`d1            # Cloudflare D1
turso         # Turso / libSQL
rqlite        # rqlite
datasette     # Datasette
starbasedb    # StarbaseDB
sqlite-cloud  # SQLite Cloud`}</Codeblock>

    <P>This target points at D1:</P>

    <Codeblock>{`[target]
type = "d1"
database = "my-db"
account_id = "abc123"
api_token = "..."`}</Codeblock>

    <P>This one at Turso:</P>

    <Codeblock>{`[target]
type = "turso"
url = "https://my-db.turso.io"
auth_token = "..."`}</Codeblock>

    <P>Same config file, same commands, same diff engine, different profile. If you have a new LIKE backend that speaks HTTP SQL, write a profile. No pull request to core required.</P>

    <P>Transforms between UNLIKE backends, like schema bridging or PII filtering, live in smugglr+. The OSS tool syncs any number of LIKE sources from a single config. That is the moat.</P>
</Section>

<Section id="shapes" title="Shapes." tint>
    <P>One engine, five shapes. The base case is direct sync. The rest are variants for when the network, the schedule, or the recovery story is different.</P>

    | Shape | Commands | When |
    |-------|----------|------|
    | **Direct sync** | `push`, `pull`, `sync`, `diff` | Everyday case. Source and target are both reachable from where smugglr is running. |
    | **Watch daemon** | `watch` | Continuous background sync on a fixed interval. JSONL per tick. |
    | **S3 relay** | `stash`, `retrieve` | Machines that cannot see each other. Upload the diff to S3, another machine pulls it. |
    | **LAN broadcast** | `broadcast` | Same subnet. Encrypted UDP peer discovery, no coordinator, no server. |
    | **Snapshot and restore** | `snapshot`, `snapshots`, `restore` | Point-in-time backup to the relay. Portable across backends. Snapshot from D1, restore to Turso. |

    <P>Every command takes <code>--output json</code>. Every command has a typed exit code. Details in the <a href="/docs/cli-reference/">CLI reference</a>.</P>
</Section>

<Section id="ship" title="How it ships.">
    <P>Smuggler ships three ways. <code>cargo install smugglr</code> for the native CLI, with pre-built binaries for macOS, Linux, and Windows. <code>cargo add smugglr-core</code> to embed the engine in a Rust service. <code>npm install smugglr</code> for the WASM build in Node, Bun, or a modern browser. Same algorithm, same adapters, same verbs.</P>
</Section>
