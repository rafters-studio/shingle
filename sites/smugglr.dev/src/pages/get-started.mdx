    <P slot="description">Install smugglr, point it at two SQLite files, dry-run the push to see what would change, then push. Every block below was captured from the 0.5.0 binary against the Westwind sample that ships in the repository; the same steps work on any two files whose tables share a globally unique primary key.</P>

<Section id="install" title="1. Install.">
    <P>Two binaries. <code>smugglr</code> is the CLI; <code>smugglr-http-sql</code> is the plugin every hosted backend is reached through, and this page does not need it. Cargo is the recommended install; pre-built binaries and the installer script are on the releases page.</P>

    <Codeblock>{`cargo install smugglr`}</Codeblock>

    <P>Confirm it works:</P>

    <Codeblock>{`smugglr --version`}</Codeblock>
</Section>

<Section id="configure" title="2. Configure." tint>
    <P>Create a <code>config.toml</code> in your project directory: where the local SQLite lives, and what the target is. This is the configuration from <a href="https://github.com/rafters-studio/smugglr/tree/main/docs/examples/cli-sqlite-to-sqlite">cli-sqlite-to-sqlite</a>, two files on one machine.</P>

    <Codeblock>{`local_db = "./local.db"

[target]
type = "sqlite"
database = "./backup.db"

[sync]
tables = []
timestamp_column = "updated_at"
conflict_resolution = "local_wins"`}</Codeblock>

    <P>The target must already have the tables; smugglr moves rows, not DDL. <code>type</code> is <code>sqlite</code> or <code>plugin</code>; Turso, rqlite, Datasette, StarbaseDB, and SQLite Cloud go through <code>type = "plugin"</code> with <code>name = "http-sql"</code> and the vendor in <code>profile</code>, which needs the second binary. D1 is not reachable in 0.5.0 (smugglr#429, #430, #436). See the <a href="/docs/configuration/">Configuration reference</a> for every option.</P>
</Section>

<Section id="dry-run" title="3. Dry-run.">
    <P>See what the push would do before doing it. Dry-run reads both sides, hashes every row, diffs, and reports. Nothing is written.</P>

    <Codeblock>{`$ smugglr push --dry-run
--- Push Summary ---
  order_details: 788 rows
  suppliers: 8 rows
  employees: 9 rows
  shippers: 3 rows
  categories: 8 rows
  products: 20 rows
  customers: 40 rows
  orders: 320 rows

  (dry run - no actual changes made)`}</Codeblock>

    <P>One line per table with rows to move. Run it as many times as you like. It is safe. The timestamped INFO lines smugglr also writes to stderr are not shown; the block is stdout.</P>
</Section>

<Section id="push" title="4. Push." tint>
    <P>When the dry-run looks right, drop the flag.</P>

    <Codeblock>{`$ smugglr push
--- Push Summary ---
  suppliers: 8 rows
  products: 20 rows
  employees: 9 rows
  customers: 40 rows
  order_details: 788 rows
  categories: 8 rows
  orders: 320 rows
  shippers: 3 rows`}</Codeblock>

    <P>Same counts as the dry-run; the lines come out in whichever order the set iterates. smugglr pushes only the rows whose content hash differs, batched to the target's limits. Exit code 0 means success. Push again and there is nothing to move:</P>

    <Codeblock>{`$ smugglr push

--- Push Summary ---
  No changes to push`}</Codeblock>
</Section>
